# Capítulo 4: Conclusão

### 4.1. Análise Crítica e Conclusões do Projeto
O desenvolvimento do ActiveFrame atingiu com sucesso quase todos os objetivos propostos na fase inicial da nossa proposta de trabalho. A utilização de tecnologias puras do lado do cliente (*Vanilla Architecture*) provou ser uma escolha eficaz para consolidar os conceitos de manipulação de dados estruturados em background e controlo dinâmico do DOM. 

A maior conquista do grupo residiu na criação de uma interface coesa onde os elementos multimédia (fotografia) operam em perfeita sintonia com as métricas físicas e alimentares para potenciar a motivação do utilizador.

### 4.2. Trabalho Colaborativo e Controlo de Versões (GitHub)
O repositório no GitHub foi estruturado de forma rigorosa com pastas bem definidas (`/src` para o código-fonte e `/doc` para a documentação). O uso da organização e do controlo de versões permitiu que os membros do grupo trabalhassem no mesmo código de forma sincronizada e segura.

### 4.3. Trabalho Futuro
Como linhas de evolução para uma futura versão "ActiveFrame 2.0", identificam-se as seguintes melhorias:

* **Migração do Back-End:** Substituição do armazenamento local por uma base de dados relacional real gerida por uma API em NodeJS ou PHP.
* **Dashboard Analítico:** Integração de um painel de estatísticas visuais através de gráficos dinâmicos (recorrendo a bibliotecas como Chart.js) para analisar a evolução do peso e o balanço calórico diário do utilizador.
* **Reforço dos Parâmetros de Segurança:** Implementação de políticas de segurança estritas no ecrã de registo de novas contas. Isto inclui a validação obrigatória da força da password em tempo real através de expressões regulares (Regex) no JavaScript, exigindo uma combinação robusta de letras maiúsculas, minúsculas, números e caracteres especiais antes de permitir a criação do perfil.
